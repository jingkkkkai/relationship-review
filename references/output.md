# ELI5 HTML

此為 [分階段流程](staged-workflow.md) 的最後階段。閱讀期間不反覆產出報告；內容與脈絡核對完成後，再用程式重用既有原文與片段索引，集中產出一份整合 HTML。不要讓模型重新抄寫整份對話或每批重做版面，亦不得為減少用量省去來源及覆蓋檢查。

交付名稱建議 `關係回顧_網頁圖解.html`。只交付這一份，內含關係分析與完整對話回顧，以頁內連結互相切換，不另交付第二份 HTML。不要額外產出 PDF、發布網站或加入其他聊天室的私密資料。不要把 ELI5 寫成幼兒口吻；用大圖解、短段落、具體例子與可展開細節。

## 固定版面順序

整份 HTML 只有以下五個主要區塊，依此順序；細節以子標題和展開欄呈現，不改變原有內容功能：

1. **注意事項**：依 [資料用途與隱私](data-use.md)，標示資料來源、日期範圍、已讀範圍與附件缺口、輸入／產出僅限本次報告、不另存任何可操作的記憶層、郵件／手機部分遮蔽及仍有私密內容。說明平台自動保存／記憶／訓練設定不能由 skill 保證。不要把結論放在提醒之前。
2. **關係總結**：3–5 個有條件的重點、雙方各自責任與改善方向、給雙方的支持與安慰、整體建議、跨事件模式及心理學探索（我／對方／共同）。維持有溫度、非診斷的語氣，不提供去留裁決。
3. **關係如何變化**：依互動的實際轉折分階段，例如有證據時可用「五至六月：互動升溫」「七至八月：磨合增加」。這只是例子，不是預設類型或時間表。階段可以跨月、同月內有多個轉折，或資料僅支持一個階段；不固定逐月、不硬切等長。每段呈現名稱、大約期間、如何轉變、雙方各自的需求與可調整方向，連到相關事件和完整片段。需求區分明說／推測，累積影響保留其他解釋；不由時間或訊息數推定因果。日期不明、空白期及階段分界不確定時說明，不補造關係狀態，也不能只挑爭執決定階段。
4. **事件回顧**：事件選單、依時間排列的事件分析，含雙方立場、優點、責任、練習、補述條件式分析及未知；每個事件另有「這次互動的心理學觀察」，分我／對方呈現有依據的當次反應或資料不足說明，依 [事件心理學觀察](tone-and-concepts.md#事件內的心理學觀察) 執行。「查核依據與來源」收合放本區末尾，不另成第六主章。
5. **完整對話：依氣氛分類**：同一份 HTML 最後，五類氣氛、日期、搜尋、可展開的完整對話。包含可安全呈現的附件與明確引用，見 [聊天格式](chat-style.md)。

### 階段內的需求與調整也要整合

每個階段只呈現一組四欄：「我在這階段的核心需求」「對方在這階段的核心需求」「我在這階段可調整的方向」「對方在這階段可調整的方向」。即使階段橫跨數月，也不要在這些欄位再按月份、每次爭執或事件逐一重列。

- 先整合整段期間支持的核心主題，相同或相近需求合併，通常各保留 1–3 個真正有用的重點。不要把每次的小偏好全升格成階段核心需求；單次但重要的線索要標示適用範圍，不能假裝它貫穿全段。
- 調整方向也以階段的互動難題為單位，聚焦少量可延續的做法，不為每月另配一套建議。具體例子只在幫助理解時簡短帶一個，其餘由證據連結回事件和原文。
- 原始支持、反例和明說／推測的區分仍保留。並存但不同的需要不要為簡短硬合成同一件事；若核心需求真的出現重要轉折，回到階段劃分重新評估，不把變化磨平。
- 例如某個跨月的磨合階段，可整合為「我希望變動前有參與討論的空間」「對方希望自己的限制與提議被聽見」；實際必須有該階段紀錄支持，不將這個例子當通用解讀。

概覽用抽象互動箭頭／階段卡片，不重演私密場景、不用私人肖像。內容功能不因重排而省略，長文透過展開改善閱讀。

整體回顧必須依 [跨事件與時間變化](patterns.md) 探索重複模式、前後期差異、可能原因及累積影響，不只串接各事件摘要。資料不足時明說不能辨識，不強迫每份報告都有模式。用有同理心的諮商取向語氣，具體理解努力、需求和負荷，同時清楚描述責任；不自稱心理諮商師。

使用內附 renderer 時，將每個模式放入 `overall` 的可展開條目；以相鄰條目分開呈現「觀察與時間變化」「可能原因與其他解釋」「可嘗試的調整」，並在標題帶同一模式編號。`evidence_ids` 指向跨事件的原始證據及重要反例，條目文字列出事件 ID／日期。如此不需修改 renderer 也能呈現完整分析。概覽可顯示前後期回應差異，但不得把尚待確認的原因寫成確定箭頭。模式索引留工作資料夾，必要的支持、反證與未知仍呈現在 HTML，不只藏在內部。

可用內附 renderer，也可依同樣要求製作更好的 HTML。renderer 只接受已分析核對的 JSON，所有內容為純文字，不以 HTML 插入來源。

輸出前依 [文字潤稿規則](tone-and-concepts.md) 完整檢查一次所有模型撰寫的讀者文字：修主詞不明、長句、跳躍轉折、官腔、重複與稱呼切換；保留原文、依據、條件及責任，不因潤稿重做整份資料閱讀。單純成功產出 HTML 不代表文字已通順。

產出前必須通過 [完整閱讀與交付檢查](reading-gate.md)，將 `reading_audit` 加入下方 JSON。缺閱讀紀錄、有文字缺口或可讀圖片尚待處理時，內附 renderer 會拒絕產出；不得刪除檢查、補造已讀紀錄或改用另一個模板繞過。HTML 中的 `coverage` 要以白話說明實際閱讀範圍及附件缺口，不把清單核對稱為理解保證。

## 每份報告須有的內容

- **事件內**：雙方立場與經過、各自責任、各自可以怎麼調整、當次雙方心理學觀察、依據與未知。心理觀察涵蓋有幫助的反應，不只列問題；不因一次反應推斷穩定人格或習慣。重要補述增加「如果把這段補充也考慮進來」的條件式展開欄，依 [補充事件](supplements.md) 說明結論如何改變並緊鄰注記，不能只埋在來源表。
- **整體回顧內**：分別呈現「我可以承擔的部分」「對方可以承擔的部分」「我可以嘗試的調整」「對方可以嘗試的調整」「給我的話」「給對方的話」「這段關係的整體回顧與下一步」。可按脈絡改標題，但上述功能不可省略。不足以判斷責任時明說，不為填欄位發明過錯；不預設各半。
- **模式與時間變化**：保留已有的跨事件比較、原因假說、反例與建議。上述整體欄位是整合，不機械重複所有事件。
- **可以探索的心理學概念**：固定分「我可以探索的概念／對方可以探索的概念／共同可以探索的概念」三部分，依 [溫暖敘述與探索關鍵字](tone-and-concepts.md) 提供概念、白話說明、相關事件、限制、來源及可討論的問題。三組不必等量，無適用概念時保留該組並說明，不硬套。

條件、敘事來源、推論與概念限制必須在相關段落可見；首屏的簡短結論也不能將它們省略成已證實的事實。不要把未確認補述視為無關，也不要因補述直接改寫原始證據。

使用內附 renderer 時：事件內容放 `events[].sections`，整體責任／改善／支持／總結放 `overall`；探索概念另放必要的 `concepts.self`、`concepts.other`、`concepts.shared`。每組有 `summary`（白話引介或無適用概念原因）及 `items`；每個 item 用 `title, text, evidence_ids`。缺三組時工具拒絕產出，不把概念混回 overall。心理學定義來源以 URL 放在 `text` 並明確命名；renderer 會將網址轉成可點擊外部來源，不讀取外部內容。`evidence_ids` 仍指向個案紀錄／補述，不以理論來源代替。未獨立確認的補述在來源表標為「事後回憶／當事人補述」，並在事件欄再次標示「如果成立」的條件。一般建議不必假裝是已發生的事實。

```text
python3 scripts/render_html.py /path/work/report.json /path/outputs/關係回顧_網頁圖解.html --archive /path/work/archive.json --materials-root /path/work/materials
```

JSON 欄位（非使用者填寫格式；另依 reading-gate.md 加入實際 `reading_audit`，依 conversation-review.md 建立對應的 archive.json 並將回顧內嵌於同一 HTML）：

```json
{
  "conversation_index": {"section_id":"conversation-review", "segment_ids":["C001"]},
  "title": "關係回顧",
  "scope": "2026/06/01–2026/06/30；LINE 文字與兩筆事後回憶",
  "coverage": "所有選定文字已讀。TXT 的圖片標記沒有對應圖片，未讀電話內容。",
  "takeaways": ["分工是這段互動的一個優點。"],
  "stage_review": [{
    "title":"一起安排、互相配合", "period":"2026 年六月的可見互動", "segment_ids":["C001"], "summary":"階段依互動方式劃分；目前只有這段資料，不推論其他時間。",
    "self_needs":{"text":"示例：依實際階段原文填需求，推測須標示。", "evidence_ids":["LINE-L000123"]},
    "other_needs":{"text":"示例：依實際原文填寫，不能判斷時明說。", "evidence_ids":[]},

    "other_improvements":{"text":"示例：尊重對方選擇的建議。", "evidence_ids":[]}
  }],

    "id": "E001", "title": "準備旅行", "date": "六月上旬，日期未定",
    "summary": "先分工，討論預算後重新確認安排。",
    "psychology": {
      "self":{"summary":"依當次脈絡說明；不足時明說，不強行配上術語。", "items":[]},
      "other":{"summary":"同樣核對對方的回應與後續修復，不推定內心動機。", "items":[]}
    },
    "sections": [
      {"title": "雙方立場", "text": "依各自明說的內容整理。", "evidence_ids": ["LINE-L000123", "S001"]},
      {"title": "做得好的地方與責任", "text": "具體行為及其影響。", "evidence_ids": ["LINE-L000123"]},
      {"title": "可以練習", "text": "可執行的小步驟。", "evidence_ids": []},
      {"title": "仍不知道", "text": "線下討論內容沒有紀錄。", "evidence_ids": []}
    ]
  }],
  "overall": [{"title": "值得保留的方式", "text": "以真實證據支持的整體回顧。", "evidence_ids": ["LINE-L000123"]}],
  "concepts": {
    "self": {"summary":"依實際分析填寫適合你探索的方向；不足時說明原因。", "items":[]},

```

依據放同一 HTML 中供離線查找，source 保存原檔及位置；重點摘錄之外必須可連到完整話題片段與必要的更早約定，不能用幾句摘錄代替讀者查核所需脈絡；依 [全部對話與完整脈絡](conversation-review.md) 執行。主文中的實質結論必須連到證據，不能以整份檔案籠統背書。練習是建議，不偽裝成訊息事實。無法分享完整來源時，仍保留回查位置。

所有來源文字與名稱先做郵件／手機顯示遮蔽，再做 HTML escaping；不直接插入訊息 HTML／SVG／JS。無遠端字型、追蹤、網路依賴或外部附件自動載入；原始分享／外部附件連結僅供手動點擊，本機附件經檢查後嵌入同一 HTML，不建立外部素材資料夾。不需要連模型就能切換事件與展開依據。控制長文與換行，寬窄螢幕可讀。角色標籤預設固定為「我／對方」，僅使用者特別指定時才統一用替代名稱；不自動套用匯出名稱。安慰與建議的內文可自然稱呼讀者「你」，原文不作強制代名詞替換。

完整對話的可見格式依 [社群聊天閱讀格式](chat-style.md) 固定：名字與時間、左右氣泡、日期分隔、原文與短標記，不顯示 JSON 欄位或來源路徑。依據區也只顯示白話來源種類；`source` 與原始位置留工作資料供查核，不直接印出。不得為隱藏來源而破壞證據 ID、完整片段連結或紀錄覆蓋。

最後提供可點擊下載的 HTML 路徑及簡短開啟方式。說明本次實際驗證範圍，不宣稱未測的平台正常。工作用 coverage、時間線、正規化資料與 report JSON 留在工作資料夾，不混進主要交付檔案。

## 完整對話回顧與交付檢查

依 [全部對話與完整脈絡](conversation-review.md) 生成五類回顧，訊息依據須有 `context_segment_ids` 連到完整片段；主報告附 `conversation_index` 指定頁內區塊及有效片段 ID。內附 renderer 對訊息來源強制要求脈絡連結，補述來源維持獨立標示，不能冒充聊天片段。正式交付前核對同一 HTML 的頁內連結及錨點有效、每筆原始紀錄都有歸屬、氣氛篩選與上一段／下一段能正常使用。

同一檔案內含完整私密對話（郵件／手機已部分遮蔽），即使回顧區預設收合也不等於資料被移除或遮蔽。交付時提醒分享前檢視整份內容；若另需分享版，須經使用者要求再處理。所有區塊都通過完整閱讀門檻後才一起交付。大量紀錄以收合、搜尋及頁內定位改善閱讀，不擅自改成多檔或只放抽樣。

`stage_review` 為必要欄位，取代逐月回顧；各階段包含 `title, period, summary, segment_ids` 與四組 `self_needs, other_needs, self_improvements, other_improvements`。四組用 `text, evidence_ids`，內容須整合整個階段，不建立逐月子清單；不知道時明說。`period` 是如實的大約時間描述，不必精確到日。`segment_ids` 為主階段歸屬，依 archive 既有片段順序連續完整涵蓋、每片段恰好一次；比較早期／後期的反例可用 evidence_ids 連回其他階段，不重複歸屬。跨轉折片段先核對主題界線再合理切段，不能為配合月份碎切原文。工具只核對完整覆蓋和有效連結，不會判定階段分析是否合理。

每個事件的 `psychology` 固定有 `self`、`other`；各組必填 `summary` 和 `items`。items 每項仍用 `title, text, evidence_ids`，但必須有實際證據連結，理論 URL 不算個案證據。`text` 寫出當次可觀察的反應、可能的心理概念／作用、當次後續與其他解釋，以及可嘗試的調整；理論定義查核來源亦放其中。沒有足夠資料或不需套概念時用空 items，summary 白話說明原因。不得因新增欄位就替雙方各發明一個心理問題；總結中的我／對方／共同概念區仍保留，負責跨事件統整。

既有資料若只改版面或加入這些欄位，重用已完成的原文索引、事件分析與依據，核對相關片段後整理階段與當次反應；不用為重繪而再讀全部紀錄。新的實質解讀仍需回查相應前後文，資料不足不能把舊摘要當完整證據。
