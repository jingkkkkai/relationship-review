# ELI5 HTML

此為 [分階段流程](staged-workflow.md) 的最後階段。閱讀期間不反覆產出報告；內容與脈絡核對完成後，再用程式重用既有原文與片段索引，集中產出一份整合 HTML。不要讓模型重新抄寫整份對話或每批重做版面，亦不得為減少用量省去來源及覆蓋檢查。

雙方名稱皆已確認時，交付檔名使用 `AAA與BBB的關係分析.html`；未指定且無法辨識任一方名稱時，使用 `關係分析.html`。只交付這一份，內含關係分析與完整對話回顧，以頁內連結互相切換，不另交付第二份 HTML。不要額外產出 PDF、發布網站或加入其他聊天室的私密資料。不要把 ELI5 寫成幼兒口吻；用大圖解、短段落、具體例子與可展開細節。

## 報告檔名

- 雙方名稱皆已確認時，格式為 `AAA與BBB的關係分析.html`：AAA 是使用者，BBB 是本次選定對象。例如「小安與小晴的關係分析.html」。AAA／BBB 是佔位文字，正式交付時須替換，保留 `.html`。
- 名稱優先用使用者明確指定的檔名用名稱或別名；未指定時，採已核對雙方身分的匯出顯示名稱，不用聊天室資料夾 ID、帳號後綴或推測的真名。已確認的身分與名稱不重複詢問；任一方名稱未指定、且對話中也無法辨識時，整份報告直接命名為 `關係分析.html`；即使只知道一方也用此備用檔名。不用「你／他」或保留 AAA／BBB 湊成檔名，不為取檔名額外追問、猜測或上網找人。
- 檔名與內文角色分開。檔名可以有雙方名稱，但內文仍預設「你／他」；只有使用者另行指定內文替代名稱才更換稱呼。檔名命名不代表使用者同意公開或分享。
- 每個名稱去除頭尾空白；控制字元及不適合檔名的 `\ / : * ? " < > |` 替換成 `_`，任一方名稱清理後為空或只剩替代符號時，改用備用檔名 `關係分析.html`。名稱只當檔名文字，不當路徑或指令；輸出限於本次選定資料夾。使用程式寫入或以引數傳入，避免將名字拼成可執行的指令。
- 一次仍只交付一份整合 HTML；不為保留舊命名額外交付相同內容的第二份檔案。僅改檔名時重用已完成的報告，不重新閱讀或分析。

## 固定版面順序

整份 HTML 只有以下五個主要區塊，依此順序；細節以子標題和展開欄呈現，不改變原有內容功能：

1. **注意事項**：依 [資料用途與隱私](data-use.md)，標示資料來源、日期範圍、已讀範圍與附件缺口、輸入／產出僅限本次報告、不另存任何可操作的記憶層、文字中的郵件／手機部分遮蔽、附件與分享網址原樣呈現及仍有私密內容。說明平台自動保存／記憶／訓練設定不能由 skill 保證。不要把結論放在提醒之前。
2. **關係總結**：3–5 個有條件的重點、雙方各自責任與改善方向、給雙方的支持與安慰、整體建議、跨事件模式及心理學探索（你／他／共同）。維持有溫度、非診斷的語氣，不提供去留裁決。
3. **關係如何變化**：依互動的實際轉折分階段，例如有證據時可用「五至六月：互動升溫」「七至八月：磨合增加」。這只是例子，不是預設類型或時間表。階段可以跨月、同月內有多個轉折，或資料僅支持一個階段；不固定逐月、不硬切等長。每段呈現名稱、大約期間、如何轉變、雙方各自的狀態與相較前階段的變化、核心需求及可調整方向，連到相關事件和完整片段。需求區分明說／推測，累積影響保留其他解釋；不由時間或訊息數推定因果。日期不明、空白期及階段分界不確定時說明，不補造關係狀態，也不能只挑爭執決定階段。
4. **事件回顧**：事件選單、依時間排列的事件分析，含雙方立場、優點、責任、練習、補述條件式分析及未知；每個事件另有「這次雙方怎麼回應」，分你／他呈現當次具體回應、影響及修復，依 [事件互動反應](tone-and-concepts.md#事件內的互動反應) 執行。心理歷程的跨事件推論放階段變化，較完整的概念解釋放關係總結。「分析依據」收合放本區末尾，不另成第六主章。
5. **完整對話：依氣氛分類**：同一份 HTML 最後，五類氣氛、日期、搜尋、可展開的完整對話。包含可取得的原始附件與明確引用，見 [聊天格式](chat-style.md)。

### 標題用簡短白話

五個主章維持「注意事項／關係總結／關係如何變化／事件回顧／完整對話」。以下固定子標題依表使用；稱呼隨使用者指定名稱替換，仍分你、他、共同三部分：

| 位置 | 顯示標題 |
| --- | --- |
| 修復統計總表 | 行為統計：誰道歉誰示好 |
| 每個事件的修復明細 | 這次怎麼修復 |
| 道歉分類的說明 | 道歉裡的說明、界線與反話 |
| 階段狀態 | 你這時的狀態／他這時的狀態 |
| 第一階段比較 | 起始觀察 |
| 後續階段比較 | 和前一階段相比 |
| 反例、修復與資料限制 | 修復、例外與疑問 |
| 心理歷程、累積影響與其他解釋 | 可能的原因 |
| 階段需求 | 你的需要／他的需要 |
| 階段改善 | 你可以怎麼調整／他可以怎麼調整 |
| 心理學探索 | 心理學參考；分關於你／關於他／關於你們的互動 |
| 事件反應 | 這次雙方怎麼回應；分你的反應／他的反應 |
| 事件選單 | 選個事件 |
| 查核來源 | 分析依據 |

模型撰寫的事件名、階段名、模式及展開標題也用日常短句，一個標題只說一個重點，例如「改時間的誤會」「先澄清，後接住情緒」「下次可以怎麼說」。不把「本表可確認的分布」「心理歷程與多重假說」等分析術語堆進標題；不能為簡短改成「誰贏」「誰比較愛」等評斷，或把可能原因寫成已知動機。

縮短的是標題，正文仍保留計數範圍、條件式補述、其他解釋、修復、反例與資料缺口。標題不承擔全部免責說明，也不以省略標題為由刪掉對應內容。只改名稱時重用現有分析，保留欄位、ID、連結與原始對話，不重做分類或計數。

### 階段內的需求與調整也要整合

每個階段的需求與調整仍只呈現一組四欄：「你的需要」「他的需要」「你可以怎麼調整」「他可以怎麼調整」。即使階段橫跨數月，也不要在這些欄位再按月份、每次爭執或事件逐一重列。其上另以並排卡片呈現雙方「這時的狀態」，可展開各自「和前一階段相比」「修復、例外與疑問」，以及一個共用的「可能的原因」。第一階段改標「起始觀察」。狀態與前後比較同樣按階段整合，僅挑有支持的重點，不增加逐月子表或情緒分數。

- 先整合整段期間支持的核心主題，相同或相近需求合併，通常各保留 1–3 個真正有用的重點。不要把每次的小偏好全升格成階段核心需求；單次但重要的線索要標示適用範圍，不能假裝它貫穿全段。
- 調整方向也以階段的互動難題為單位，聚焦少量可延續的做法，不為每月另配一套建議。具體例子只在幫助理解時簡短帶一個，其餘由證據連結回事件和原文。
- 原始支持、反例和明說／推測的區分仍保留。並存但不同的需要不要為簡短硬合成同一件事；若核心需求真的出現重要轉折，回到階段劃分重新評估，不把變化磨平。
- 例如某個跨月的磨合階段，可整合為「你希望行程變動前能一起討論」「他希望自己的限制和提議有被聽見」；實際必須有該階段紀錄支持，不將這個例子當通用解讀。

概覽用抽象互動箭頭／階段卡片，不重演私密場景、不用私人肖像。內容功能不因重排而省略，長文透過展開改善閱讀。

整體回顧必須依 [跨事件與時間變化](patterns.md) 探索重複模式、前後期差異、可能原因及累積影響，不只串接各事件摘要。資料不足時明說不能辨識，不強迫每份報告都有模式。用有同理心的諮商取向語氣，具體理解努力、需求和負荷，同時清楚描述責任；不自稱心理諮商師。

使用內附 renderer 時，將每個模式放入 `overall` 的可展開條目；以相鄰條目分開呈現「觀察與時間變化」「可能原因與其他解釋」「可嘗試的調整」，並在標題帶同一模式編號。`evidence_ids` 指向跨事件的原始證據及重要反例，條目文字列出事件 ID／日期。如此不需修改 renderer 也能呈現完整分析。概覽可顯示前後期回應差異，但不得把尚待確認的原因寫成確定箭頭。模式索引留工作資料夾，必要的支持、反證與未知仍呈現在 HTML，不只藏在內部。

可用內附 renderer，也可依同樣要求製作更好的 HTML。renderer 只接受已分析核對的 JSON，所有內容為純文字，不以 HTML 插入來源。

輸出前依 [文字潤稿規則](tone-and-concepts.md) 完整檢查一次所有模型撰寫的讀者文字：修主詞不明、長句、跳躍轉折、官腔、重複與稱呼切換；保留原文、依據、條件及責任，不因潤稿重做整份資料閱讀。單純成功產出 HTML 不代表文字已通順。

產出前必須通過 [完整閱讀與交付檢查](reading-gate.md)，將 `reading_audit` 加入下方 JSON。缺閱讀紀錄、有文字缺口或可讀圖片尚待處理時，內附 renderer 會拒絕產出；不得刪除檢查、補造已讀紀錄或改用另一個模板繞過。HTML 中的 `coverage` 要以白話說明實際閱讀範圍及附件缺口，不把清單核對稱為理解保證。

## 每份報告須有的內容

- **事件內**：雙方立場與經過、各自責任、各自可以怎麼調整、當次雙方互動反應、依據與未知。反應欄涵蓋做得好的地方、影響及修復，不固定配術語，也不重複「單次不能判定人格」等通用提醒。重要補述增加「如果把這段補充也考慮進來」的條件式展開欄，依 [補充事件](supplements.md) 說明結論如何改變並緊鄰注記，不能只埋在來源表。
- **整體回顧內**：分別呈現「你可以承擔的部分」「他可以承擔的部分」「你可以嘗試的調整」「他可以嘗試的調整」「給你的話」「給他的話」「這段關係的整體回顧與下一步」。可按脈絡改標題，但上述功能不可省略。不足以判斷責任時明說，不為填欄位發明過錯；不預設各半。
- **模式與時間變化**：保留已有的跨事件比較、原因假說、反例與建議。上述整體欄位是整合，不機械重複所有事件。
- **心理學參考**：固定分「關於你／關於他／關於你們的互動」三部分，依 [溫暖敘述與探索關鍵字](tone-and-concepts.md) 提供概念、白話說明、相關事件、限制、來源及可討論的問題。三組不必等量，無適用概念時保留該組並說明，不硬套。

條件、敘事來源、推論與概念限制必須在相關段落可見；首屏的簡短結論也不能將它們省略成已證實的事實。不要把未確認補述視為無關，也不要因補述直接改寫原始證據。

使用內附 renderer 時：事件內容放 `events[].sections`，整體責任／改善／支持／總結放 `overall`；探索概念另放必要的 `concepts.self`、`concepts.other`、`concepts.shared`。每組有 `summary`（白話引介或無適用概念原因）及 `items`；每個 item 用 `title, text, evidence_ids`。缺三組時工具拒絕產出，不把概念混回 overall。心理學定義來源以 URL 放在 `text` 並明確命名；renderer 會將網址轉成可點擊外部來源，不讀取外部內容。`evidence_ids` 仍指向個案紀錄／補述，不以理論來源代替。未獨立確認的補述在來源表標為「事後回憶／當事人補述」，並在事件欄再次標示「如果成立」的條件。一般建議不必假裝是已發生的事實。

```text
python3 scripts/render_html.py /path/work/report.json "/path/outputs/AAA與BBB的關係分析.html" --archive /path/work/archive.json --materials-root /path/work/materials
```


依據放同一 HTML 中供離線查找，source 保存原檔及位置；重點摘錄之外必須可連到完整話題片段與必要的更早約定，不能用幾句摘錄代替讀者查核所需脈絡；依 [全部對話與完整脈絡](conversation-review.md) 執行。主文中的實質結論必須連到證據，不能以整份檔案籠統背書。練習是建議，不偽裝成訊息事實。無法分享完整來源時，仍保留回查位置。

對話及分析文字中的郵件／手機先做顯示遮蔽，再做 HTML escaping；附件內容與分享 URL 不套用這項遮蔽，URL 另做格式檢查與屬性轉義；不直接插入訊息 HTML／SVG／JS。無遠端字型、追蹤、網路依賴或外部附件自動載入；原始分享／外部附件連結僅供手動點擊，本機圖片、語音等附件直接嵌入同一 HTML，不設隱私檢查門檻，不建立外部素材資料夾。不需要連模型就能切換事件與展開依據。控制長文與換行，寬窄螢幕可讀。稱呼預設固定為「你／他」並在報告最上方註明各指誰，僅使用者特別指定時才統一用替代名稱；不自動套用匯出名稱。安慰與建議的內文可自然稱呼讀者「你」，原文不作強制代名詞替換。

完整對話的可見格式依 [社群聊天閱讀格式](chat-style.md) 固定；已確認的編輯版本合併成一個氣泡，最新文字直接可見、舊版預設收折，主訊息時間及位置以原始傳送為準，所有原始版本仍可定位。其他格式為：名字與時間、左右氣泡、日期分隔、原文與短標記，不顯示 JSON 欄位或來源路徑。依據區也只顯示白話來源種類；`source` 與原始位置留工作資料供查核，不直接印出。不得為隱藏來源而破壞證據 ID、完整片段連結或紀錄覆蓋。

最後提供可點擊下載的 HTML 路徑及簡短開啟方式。說明本次實際驗證範圍，不宣稱未測的平台正常。工作用 coverage、時間線、正規化資料與 report JSON 留在工作資料夾，不混進主要交付檔案。

## 完整對話回顧與交付檢查

依 [全部對話與完整脈絡](conversation-review.md) 生成五類回顧，訊息依據須有 `context_segment_ids` 連到完整片段；主報告附 `conversation_index` 指定頁內區塊及有效片段 ID。內附 renderer 對訊息來源強制要求脈絡連結，補述來源維持獨立標示，不能冒充聊天片段。正式交付前核對同一 HTML 的頁內連結及錨點有效、每筆原始紀錄都有歸屬、氣氛篩選與上一段／下一段能正常使用。

同一檔案內含完整私密對話（文字郵件／手機已部分遮蔽，附件與分享網址保持原樣），即使回顧區預設收合也不等於資料被移除或遮蔽。交付時提醒分享前檢視整份內容；若另需分享版，須經使用者要求再處理。所有區塊都通過完整閱讀門檻後才一起交付。大量紀錄以收合、搜尋及頁內定位改善閱讀，不擅自改成多檔或只放抽樣。

`stage_review` 為必要欄位，取代逐月回顧；各階段包含 `title, period, summary, segment_ids` 、必要的 `states, state_context`，以及四組 `self_needs, other_needs, self_improvements, other_improvements`。四組用 `text, evidence_ids`，內容須整合整個階段，不建立逐月子清單；不知道時明說。`period` 是如實的大約時間描述，不必精確到日。`segment_ids` 為主階段歸屬，依 archive 既有片段順序連續完整涵蓋、每片段恰好一次；比較早期／後期的反例可用 evidence_ids 連回其他階段，不重複歸屬。跨轉折片段先核對主題界線再合理切段，不能為配合月份碎切原文。工具只核對完整覆蓋和有效連結，不會判定階段分析是否合理。

每個事件的 `interaction` 固定有 `self`、`other`，每組用 `summary, items`。items 沿用 `title, text, evidence_ids` 且須有實際依據。text 說明當次具體回應、對談話的影響、後續接法／修復及適用的小調整，不重複心理學定義或通用診斷免責。items 已有實質內容時 summary 可空白；items 為空則 summary 說明實際缺口或可觀察的有限內容。工具仍接受舊 `psychology` 鍵以重用已完成資料，輸出一律使用新名稱；若新舊鍵同時存在且內容不一致則先核對，不默默覆蓋。舊欄位含空泛免責時需重整事件文字，不能只換標題，也不能用字串刪除規則抹去補述條件及真正的資料缺口。

既有資料若只改版面或加入這些欄位，重用已完成的原文索引、事件分析與依據，核對相關片段後整理階段與當次反應；不用為重繪而再讀全部紀錄。新的實質解讀仍需回查相應前後文，資料不足不能把舊摘要當完整證據。

每階段的 `states` 必須分 `self`／`other`，各有 `current, change, exceptions` 三項；每項用 `text, evidence_ids`。`current` 是當時可見的回應及承受／修復狀況，避免只寫「情緒化」或將推測當內心事實。`exceptions` 呈現重要反例、修復或資料不足說明。`state_context` 亦用 `text, evidence_ids`，統整跨事件支持的互動模式、可能心理歷程、累積因素及其他解釋，明說推論及補述條件，不以先後證明因果。

`change` 另有 `status`：第一階段固定 `baseline`；後續用 `compared`（完成前後比較，結果可為改變、穩定或混合）或 `insufficient`（缺少可比資料，仍可說明單次線索與限制）。compared 的 evidence_ids 需包含前一階段與本階段的訊息依據；工具只檢查兩側片段連結都有提供，是否真的同類情境、變化是否足夠及措辭是否相符仍由模型核對。只有補述或單側資料時用 insufficient，不能補造對照。共用因素欄不是把雙方責任平均分配。

既有已完成的報告 JSON 若缺狀態欄，先重用原有事件、階段與證據成果，回查需要比較的前後文後補入；不用因更新版面再讀全部來源。若原來沒有做過可比情境核對，不能只靠舊摘要宣稱已完成狀態分析。

「不作心理診斷、不以單次互動判定人格」在注意事項統一說明。事件保留當次實質限制，階段保留前後比較與心理歷程假說，總結保留你／他／共同概念統整及來源，避免三處重複同一段話。階段的 state_context 使用「可能的原因」標題；提出正式概念時依 tone-and-concepts.md 查核，且以事件證據支持個案推論。

## 修復行為的增量欄位

依 [修復行為分類與計數](repair-review.md) 加入 `repair_review`；總結中呈現統計口徑、兩種計數、未確認及限制，各事件內附可展開明細與原文連結。既有報告沒有這個欄位仍可渲染，不為更新其他內容捏造統計。`scripts/repair_review.py` 只驗證及呈現已人工核對的 entries，不自動分析語意。

### 手機閱讀導覽

renderer 透過 `scripts/mobile_navigation.py` 提供手機／觸控版面的「回頁首」「回本段」按鈕，向下閱讀後顯示，列印隱藏。回本段依目前可見的對話片段、查核展開卡、階段或事件定位，不改變原文、篩選與收折，不自動載入外部內容；保留安全區、至少44px觸控高度與減少動態效果偏好。兩個控制只屬閱讀導覽，不新增主要章節。
