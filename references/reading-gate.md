# 完整閱讀與交付檢查

此檢查是交付條件，不是「盡量完整」的建議。先讀完，再形成跨事件整體分析及交付 HTML；可在工作資料保留暫定事件筆記，但不可提前向使用者交付片段結論或拿它代替全文分析。中途進度只報日期／檔案／筆數與剩餘缺口，不報尚未核對的心理判斷。

執行前先讀 [分階段處理與接續](staged-workflow.md)。把機械整理、全文閱讀、全局推論和輸出分開；已完成且版本未變的成果可重用，不每批重做整份分析。此處的完整閱讀門檻不變，節省的是重複工作，不是略讀。

## 怎麼知道讀到哪裡

### 閱讀執行方式

- 使用者確認資料範圍、對象與補述後，自動連續分批處理。每批可簡短回報進度，回報後立即接續，不詢問「要不要繼續」、不以進度回報作結等待回答。不固定每批 2,000 筆；依文字長度、工具回傳及完整回合調整。
- 預設自己執行；環境確實支援且使用者選擇多代理時才分工。無此能力或權限就明說並自行接續，不假稱已派代理。不為此建立新聊天，也不需要固定間隔排程。不得自行建立週期排程作為閱讀主流程。
- 多代理時，主代理分配互不重複的主要範圍、來源版本及獨立進度檔。交界可重讀前後文，但該部分標為脈絡重疊，不重算完成量。代理需讀原始內容並回傳可追查的閱讀紀錄、事件依據、反例、未解缺口，不只交摘要。
- 主代理整合前核對每區完成狀態、來源完整性與歧義；親自回查跨段事件、敏感推論、反例及關鍵模式。不能把各代理的局部結論直接相加；全部完成後仍通過相同交付門檻。
- 一份主要區段一次只由一個執行者處理；狀態包含待讀／進行中／完成及執行者。失敗重試前先確認原執行者已停止，從最後確認完成位置接續；進行中不能當已完成。skill 的文字指示不是跨 session 的自動鎖定機制，不承諾能防止外部另開工作重複執行。
- 只有真的需要缺失資料、重要範圍選擇、權限或遇到實際執行／額度限制才停下，說明具體障礙及保存的進度。不因「一批讀完」停止，不宣稱停止後仍在背景閱讀。不得以未經確認的固定閱讀上限要求使用者重複批准。

1. 從選定來源建立清單：全部分卷、每個原始訊息檔的紀錄數、補述項目、圖片與其他附件。訊息來源與分段綁定固定來源 ID、原始位置和檔案版本。JSON 全部解析成功，不等於模型讀過全部內容。
2. 將每個文字來源按原始紀錄位置分成連續且可容納的區段。完整讀取工具實際回傳的文字：若回傳被截斷、只顯示頭尾或省略中段，縮小區段重讀；不可把整段標已讀。不以命令列印整份大檔再忽略截斷提示。讀檔呼叫成功或字數統計不能作閱讀收據。
3. 每段實際讀完後，才登記來源、起訖位置、日期範圍與簡短事實筆記（非內部思考鏈）。筆記須反映本段內容，不能用程式自動替所有區段填「已讀」。程式可協助清單與缺口計算，不能自行宣告模型已理解。
4. 轉傳、系統通知與編輯版本也需逐筆識別分類；只有確認無實質互動的內容才可排除深入分析，不能先刪關鍵字之外的紀錄。所有實質訊息、正向日常與補充敘述必須讀完。
5. 每張可用圖片需真正檢視，聊天截圖中的文字納入上下文；圖片列出、縮圖生成或 OCR 執行不等於已閱讀。音訊／影片無能力處理時，如實列出範圍與可能影響，不把附件內容聲稱已知。
6. 跨分段事件回查銜接的前後回合；讀完全部後，再核對最初候選結論、反例及跨事件模式，不能只拼接局部摘要。

## 交付門檻

- 清單與實際來源一致，每一個選定文字檔／補述都列入；所有紀錄位置連續覆蓋，無缺漏。除有來源可回查的重疊閱讀外，不以重複筆數充當覆蓋率。
- 待讀文字為零；所有可讀圖片已處理。確實損壞、缺檔或工具不支援的內容逐項列為不可讀並附原因，不把沒時間讀標成不可讀。若尚有可讀的待辦內容，不得產出報告。
- 無法取得的文字來源若影響「全部讀完」條件，就停在缺口回報，不用「已讀 80%」交付整體報告。只有使用者明確改選分析範圍後才重建清單；不能擅自縮小範圍。
- 能力不足而未讀的音訊／影片等附件仍允許依既定文字及圖片範圍分析，但報告必須明示未處理，不能稱掌握全部資料或現實脈絡。重要缺口仍依原流程追問。
- 檢查是清單／收據的覆蓋核對，不是對模型是否真正理解的自動認證；不偽造收據或為了通過門檻填滿狀態。

## HTML 產出用的閱讀紀錄

`report.json` 必須附 `reading_audit`；自製 HTML 也需做同樣檢查。內附 renderer 缺此欄位或發現缺口就拒絕產出。

```json
{
  "reading_audit": {
    "sources": [
      {"source_id":"IG-message-1", "source_kind":"message", "record_count":2,
       "reviewed_ranges":[{"start":1,"end":2,"status":"read","note":"本段談旅行分工與預算確認。"}]},
      {"source_id":"supplements", "source_kind":"supplement", "record_count":1,
       "reviewed_ranges":[{"start":1,"end":1,"status":"read","note":"補述事前線下告知安排。"}]}
    ],
    "attachments":[
      {"id":"photo-1","kind":"image","status":"read","reason":"已檢視聊天截圖"},
      {"id":"audio-1","kind":"audio","status":"unavailable","reason":"本環境未能播放或轉錄，報告列為缺口"}
    ]
  }
}
```

`record_count` 是各來源清單中的原始紀錄數，不是推估人類發言數。區段為從 1 開始、含首尾的位置。讀取版本變動時重查受影響位置。沒有補述或附件可留空，但不能遺漏實際提供的來源；renderer 只能檢查已申報清單，分析者仍須核對是否完整。
