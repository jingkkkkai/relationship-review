# 示好、承認、調整與道歉

在完成既定全文閱讀後，逐事件整理雙方可見的修復行為；關係總結呈現統計口徑與分布，每個事件附可展開明細。不以次數判輸贏、愛的程度、真心或責任多少，也不把拒絕聯絡／休息／不復合算成缺乏修復能力。使用者只要求其他局部修改時，不為補表強迫重做全文。

## 先確認行為，再計數

- **示好 goodwill**：衝突或疏離後，實際表達關心、珍惜、邀請修復或重新靠近。一般日常、禮物、性邀請、愛心、接受一次見面不自動算修復；有幫助與否、對方是否願意分開記。拒絕後追傳或連打即使自稱示好，也不能列為正向示好。
- **承認自己的部分 responsibility**：當下承認自己誤解、用詞或具體行為有問題。「都是我的錯」需核對是承認還是反諷／抗議；用這項取代籠統的「低頭」。
- **讓步或調整 adjustment**：接受可協商安排、同意暫停、撤回指控或真的改變做法。承諾與已做到分開寫，不把一個「好」猜成全面認錯；停止侵害是應做的改正，不換取對方親密或原諒。
- **道歉 apology**：當下向本次對象為特定行為或影響表達歉意。承認事實不必硬加道歉標籤。要求道歉、說不必道歉、否認歉意、回述「我以前有道歉」、未寄草稿、第三人故事、引用、模型生成及社交客套不算當次道歉；另外記原因。

對道歉再作語意註記，可多選：`direct` 明確致歉、`explanation` 另述原意／原因、`boundary` 保留立場／界線、`impact_qualified` 如果有讓你難受等限定、`conditional_exchange` 以對方先認錯等作前提、`negating` 致歉後撤回承擔或明確轉責、`irony` 有上下文支持的反諷、`uncertain` 指涉或語氣仍不明。這些是說法和功能的辨識，不是內心真偽鑑定。

「但／如果／因為」不是自動分類器。「抱歉剛才罵人，但我仍不同意那個安排」可以同時有承擔和界線；說明自己受傷不自動取消歉意。相反地，不能因出現「對不起」就算清楚道歉。明顯反諷另列，不混入清楚致歉；歧義保留待確認。對方說「你的道歉是假的」是其評價，須另查原文，不直接採為分類。

## 單位、範圍與來源

1. 先重用既有完整閱讀、事件及版本索引，逐事件回查修復的起因、實際對象、內容與後續接法。關鍵字只找候選，不能按命中數自動計數；也檢視無道歉用語的承認、撤回、合作及調整。脈絡不足要擴讀，不用固定前後幾句作充分證據。
2. 一個**收錄回合**是同一人、同一議題的一段連續修復表達；連續短訊、重複致歉、版本編修合併一次。重啟或改談另一具體傷害時才另記，並保留合併理由。分組不是客觀自然常數，須在報告說明口徑。回合可有多種類行為，類別數不能相加當總數。
3. 同一編輯鏈不重算。若道歉是後來版本才加入，較早可見時間依該版來源時間，不能因氣泡放在原始時間就提前認定道歉。舊版被刪掉的承擔需另標示，不假裝最新版仍保留。
4. 訊息裡實際做出的行為、對話中的歷史主張、線下補述、草稿、推論及未知分開。補述以「如果符合實況」記錄，與可定位的訊息行為分表分數，不把未送信當已道歉；附件內容未讀就不能由檔名或送出檔案推定其有道歉。
5. 同時顯示**本表確認的回合數**與**有此行為的事件數**，以及未確認／不適用。不能把未確認寫成沒做。只收錄有足夠依據的回合時，明說是可核對下限，不稱全關係總次數；要宣稱完整計數，需有逐項分類與排除的覆蓋查核。不得用任意幾個例子作雙方比例或排名。
6. 「誰先」限定同一個界線清楚的修復段落，分示好與道歉。能確認片段起點、時序及版本才比較；線下可能更早、段落混合多次衝突或缺電話內容時寫無法判斷。可顯示「本表中較早可定位的回合」，但不能改稱真實第一個低頭者；不要把這種下限表再算成先示好勝率。
7. 後續記為接住、局部收尾、繼續爭論、拒絕或未知；接受一句謝謝不等於原諒、復合或議題全部解決。正向修復與同回合的越界／辱罵可以並存，不能互相抵銷。

## 工作欄位與呈現

可用 `repair_review`，至少有 `method`（本次口徑／範圍／缺口）、`events`（每個既有事件的狀態與範圍）、`entries`（人工核對的回合）。每筆 entry 含唯一 id、event_id、actor、phase、categories、apology_status（clear／limited／irony／uncertain／none）、apology_styles、source_kind（message／supplement／claim／unsent）、initiative（initiated／responded／uncertain，區分主動示好與回應善意）、record_ids、context_record_ids、evidence_ids、summary、rationale、outcome、outcome_record_ids；只有實際訊息行為列入主統計。空 record_ids 僅允許非 message 來源，仍須有補述依據。

原始紀錄不刪改；工作表保存查核與排除理由，不把私人資料寫進 skill。每個實質判斷能點到原文和必要上下文。總表以「行為統計：誰道歉誰示好」為標題放關係總結，事件下以「這次怎麼修復」展示雙方明細，維持原五大區塊，不另產第二份 HTML。舊報告只需回查新增解讀所需片段；全文閱讀收據、附件、既有分析與所有引用保留。單獨提供的 HTML 必須先核實和工作模型是否同版本，不能覆蓋使用者已改內容。

程式只驗證欄位、去重、來源連結及依已核對標籤加總，不由句子自動判反諷或誠意。輸出前核對抽屜明細與各類數字一致，測試重複版本、同回合多標籤、補述排除、未知與反諷不混計、錯誤引用須拒絕。
