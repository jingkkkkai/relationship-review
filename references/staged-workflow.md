# 長資料分階段處理與接續

本流程適用所有模型，尤其是容易在長任務中結束一輪的情況。目的是減少重複整理、重讀與反覆寫報告，不省略完整閱讀，也不保證突破平台額度。它補足 reading-gate.md 的執行方式，不取代任何交付門檻。

## 狀態與成果放在檔案，不只留在聊天

完成對象、範圍、補述與執行方式確認後，在本次工作資料夾建立：

- `source-manifest.json`：選定來源、固定來源 ID、檔案版本指紋、紀錄數、附件索引、使用者身分與確認過的別名。固定來源、版本與位置後再分批。不得把本次私人資料寫到 skill 目錄。
- `checkpoint.json`：目前階段、已完成的批次、進行中項目、下一個具體動作、成果路徑、阻礙與更新時間。完成狀態由已落盤且核對過的成果推得，不能只信聊天中的完成宣告。
- `batches/`：每批的閱讀收據與內容筆記，包含來源版本及範圍。每個執行者用自己的檔案，主代理統整清單，不同時覆寫同一檔。
- `events/`：跨段事件連結、雙方說法、反證、待查指涉與附件。先保存觀察，暫定解讀明確標示未核對。

這些是接續所需的工作成果，不是要求公開內部思考鏈，也不是額外交付給讀者的報告。短資料可合併檔案，但仍須具備同樣資訊。

階段只有四個：`prepare` → `read` → `synthesize` → `render`；另有 `blocked` 表示真實障礙，保留原階段及接續動作。不要把每一批當成完整任務並在完成後結束。

## 階段一：整理一次，後面重用（prepare）

用程式完成解包、編碼處理、來源清單、排序、穩定 ID、位置映射、附件清單及分批索引。程式只處理確定性的機械工作，不替模型讀內容、判意圖或依關鍵字刪掉日常。完整正規化資料保留原文及來源位置，供後續閱讀與完整回顧重用。

讀取已存在的本次工作成果，先核對來源與版本：相同資料不要重新解包、重新編號或重建整份清單。匯入有變動時只重做受影響部分；尚未閱讀的資料不能因已整理好就算已讀。

按實際文字長度與回傳限制安排區段，不固定以訊息筆數推定負荷。盡量保留完整回合，長事件可跨批但保留接續關聯。分批索引可先生成，但「已讀」不可預先填寫。

## 階段二：一次完整閱讀，留下足以接續的內容成果（read）

持續執行下列循環，直到選定文字、補述與可讀圖片都完成：

1. 檢查 checkpoint 及已完成收據，找第一個未完成區段；確認沒有另一個執行者正在處理相同主要範圍。
2. 顯示並完整閱讀該段原文。檢查回傳是否截斷；有截斷先縮小區段，不把未顯示部分算已讀。必要圖片在同段檢視，重複引用同一圖片可重用已核對的檢視紀錄。
3. 保存**內容成果，不只一行「已讀」**：時間範圍、所談事項、雙方具體說法與行動、正向互動、未解指涉、重要支持與反證 ID、是否與前段事件延續、附件處理、暫定五類片段。補述另標來源及條件，不混成聊天事實。
4. 摘要長度隨實質內容調整：日常重複段落可簡潔，重要衝突、澄清、約定及反例要保存足夠細節。不得只留下負面或關鍵字命中的句子；原文始終可回查。筆記只為接續與定位，不能取代下一批原文閱讀。
5. 先將成果寫入暫存檔並檢查，再用安全替換方式提交批次成果，最後更新 checkpoint。中途被打斷時，沒有提交的區段仍是未完成，不能依游標已往前就算完成；恢復時只補該區段及必要交界脈絡。
6. 直接處理下一批。可以回報短進度，但不詢問是否繼續、不結束後等待例行批准、不建立排程。不要每批重寫分析、反覆讀全部已讀原文，或反覆核對整份大型成果。

閱讀期間不製作最終措辭、心理學定論、精美 HTML 或整段關係評語。暫定五類與事件指標只存工作資料，最後連接完整話題並校正，不以初次分類作永不改變的結果。

完成後核對原始清單與 coverage，一次檢查漏批、補述、圖片及跨批事件是否完整，再進入 synthesize。不是每讀一批就重新執行整份報告的所有檢查。

## 階段三：全部讀完後，再做整體理解（synthesize）

先載入精簡索引及各事件／批次的已保存內容成果，建立完整每日時間線與跨事件比較。不要為恢復上下文重新將五萬筆原文整份塞進回傳或重讀一次，也不要以極短摘要拼接假裝理解全貌。

針對重要判斷回查原文，而不是每一行都機械重讀：

- 敏感意圖、責任或心理學假說所依據的完整話題與必要前文。
- 跨段約定、事件前因後果、相反證據及修復例外。
- 記錄不足以判斷的指涉、來源變動或補述條件式分析。

依 analysis.md、patterns.md、supplements.md 及 tone-and-concepts.md 完成分析。沒有夠用的內容成果就回查相關來源補足，不能用「省用量」當理由忽略缺口。區分為查核而重讀與因遺失進度而重讀，後者應盡量避免。

整合五類片段、完整上下文連結與全部對話歸屬。在此才確定跨期行為模式、可能原因、心理學探索概念、雙方責任與改善，以及各自支持的話。新反證可撤回早期候選推論，不為保留已做工作硬湊結論。

## 階段四：內容定稿後，集中輸出（render）

定稿前依 tone-and-concepts.md 的「一次完整潤稿」檢查全部讀者文字。改善語句與銜接，不改原文、證據與判斷強度；一次集中完成，不每批反覆潤寫，也不因此重讀全部訊息。

用程式將既有正規化原文與片段 ID 組成 archive.json，避免模型手動重新抄寫全部對話。模型提供已核對的片段邊界與標籤；程式連接原文及來源位置，不能用簡短摘要取代回顧原文。

先驗證 reading_audit、全部對話歸屬、分析證據與完整片段連結，再用內附工具產出一份整合 HTML。不要每批產出一版或重新設計版面。內容未改變就重用產出成果；出現錯誤只修受影響內容與相關檢查。正式交付仍通過全部驗證，不為省量省掉檢查。

## 中斷後怎麼接續

使用者說「繼續」時，第一個動作是找本次 checkpoint，不是建立排程、重新訪談、重新全量讀檔或重做全部準備。

1. 載入 checkpoint、來源版本及最小必要索引，核對已提交成果是否存在且對應當前來源。若某個成果缺失，僅重建受影響批次，不把所有完成狀態清零。
2. 進行中區段先確認原執行者已停止；未知狀態不啟動相同工作並行。不同代理的交界重讀不增加已讀數。
3. 依 phase 和 next_action 接續。已讀部分的內容成果可重用；理解關鍵片段時照常回查原文，不把不重讀誤解成禁止查核。
4. 恢復後重讀本次執行規則：完整閱讀後交付、不用排程、連續處理、保留來源與反證。不要因舊對話曾建排程就沿用。這份 skill 不授權修改其他既有排程，也不宣稱跨 session 必能自動找回本次資料。

若真的不能再執行，保存已完成位置及下一動作，說明「已停止，沒有背景執行」。區分三種情況：工具實際錯誤／平台顯示限制／模型自身選擇暫停。只有可核對的限制提示才能稱硬性限制；否則說「本次執行已停止，原因尚未確認」，不要自行捏造 2,000 筆或單輪額度上限。

接續若需使用者按一次「繼續」，如實說明，不承諾 skill 能自行啟動下一輪；不以此改用週期排程。不因擔心將來可能到限就提前停止。若在目前環境有使用者已啟用的持續任務能力，可在原權限與範圍內使用；不能假裝能力存在或擅自另建工作。

## 精簡 checkpoint 範例

```json
{
  "phase":"read",
  "source_manifest":"source-manifest.json",
  "completed_batch_files":["batches/B001.json"],
  "active_work":null,
  "next_action":{"source_id":"chat-1","start":301,"end":600,"task":"read_original_messages"},
  "blocker":null,
  "updated_at":"依本次實際時間填寫"
}
```

範例數字不是建議固定批次大小。source-manifest 需綁來源版本，批次成果包含精確範圍與閱讀筆記。checkpoint 是狀態，不是已讀證據；完成量由閱讀收據去重計算。所有計數都是匯出紀錄數，不改稱人類發言數。

## 多代理與成本

使用者選擇且環境支援時，代理可平行執行 read 階段的獨立範圍，主代理只作一次全局整合及必要回查。分工指示包含資料邊界、必讀原文、成果格式及禁止另建排程。不要讓每個代理各寫一份完整關係報告。

多代理可能縮短等待，但可能增加重疊閱讀與整合成本，不宣稱一定更省。預設以單一執行者的可接續流程驗證。只記錄可取得的新增已讀數、查核重讀範圍及中斷原因；無實際帳務資料不估造已省用量百分比，也不承諾特定模型必定一輪完成。
