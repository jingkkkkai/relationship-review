# 大檔處理

平台上傳限制可能改變；需要精確數字時查當前官方說明，不把硬編碼上限當永久有效。過大的檔案可能根本進不了聊天。先提示可以在電腦保留目標聊天室及其附件，不要求先成功上傳整包。

## 預設：不用安裝 Python 的瀏覽器工具

正常使用不要求使用者安裝 Python。能上傳的資料由分析環境處理；無法上傳的大型 IG 匯出則先在使用者電腦篩選。

將 skill 的 `assets/IG本機篩選.html` 複製到本次可交付的輸出資料夾，提供下載連結。若環境不能交付此資源，明確說明並改用下方手動方式，不只提供使用者無法存取的安裝路徑。不要等待取得大 ZIP 才提供工具。

給使用者的操作說明：

1. 下載「IG本機篩選.html」，用電腦的新版 Chrome／Edge 等瀏覽器開啟。
2. 在頁面選 IG ZIP，按「列出對話名稱」，勾選一個私人聊天室。
3. 按「產生選定對話資料包」，下載全部 ZIP 及「IG_資料清單.json」。
4. 回到聊天，上傳全部資料包和清單。已篩選為單一對象，可省略再次選擇，必要時只確認自己的名稱。

這個特定篩選頁面沒有網路請求、外部字型或遠端程式庫，檔案在瀏覽器內整理；這不代表後續上傳及模型分析仍在本機。原 ZIP 不修改，頁面不用 LLM。名稱僅來自匯出資料，不保證目前 IG 名稱。其他聊天室只讀識別所需資料，不產出分析。

工具會按 JSON 引用保留能找到的附件，包括聊天室外的附件；保留原路徑，列出缺檔／多個匹配與不開啟的外部連結。下載清單可能含選定對象的私密資訊，只交付給本次分析流程。

### 限制與不用 Python 的退路

- 一般 ZIP 支援 stored／deflate；ZIP64、多卷、加密或瀏覽器不支援原始 deflate 解壓時，提示使用者用電腦內建解壓功能，改在同頁選「解壓資料夾」。這是正常替代路徑，不轉而要求安裝 Python。
- 候選 JSON 每檔最多 64 MiB、合計最多 256 MiB，是工具資源保護值；不代表上傳或分析上限。ZIP 模式按需讀取檔案切片，不把整個 ZIP 解壓到記憶體，但資料夾模式打包附件、產生下載仍會消耗記憶體，不保證任意大小都能處理。
- 每包可選約 50／100／200 MiB；附件不自動刪除或縮圖。單一檔案大於所選包大小、資料夾模式單附件超過 256 MiB，或訊息量超限時，提供分開上傳附件、重新匯出較短日期範圍，或使用可存取本機檔案的環境等選項，須取得使用者的範圍選擇，不默默縮小。
- ZIP 檔名須能以 UTF-8 解讀；來源結構無法識別或群組／參與者不足時不猜對象。檔案名看不懂可改選解壓資料夾或上傳小份訊息 JSON 協助辨認。
- 若瀏覽器不能選資料夾、內建解壓也失敗或打包仍超出資源，提供下方手動方式，不宣稱資料已讀取。不要用網路上不明的 ZIP 處理網站作為私密資料的預設退路。
- 所有包共同組成資料，任一包缺失就標示未取得範圍；只收到第一包不得宣稱完整。缺檔清單也需在報告呈現。工具列出／打包不等於模型已閱讀。

## 能存取本機檔案的環境

環境本身已具備 Python 且使用者明確提供路徑後，可用內附 Python 標準函式庫工具；這不是一般使用者的安裝前提：

```text
python3 scripts/ig_bundle.py list /path/export.zip --out /path/work/threads.json
python3 scripts/ig_bundle.py select /path/export.zip --index /path/work/threads.json --id T001 --out /path/work/selected
```

腳本路徑相對於此 skill 目錄。實際執行使用絕對路徑、正確參數引用。list 僅讀名稱及日期等 metadata，不輸出訊息正文。對象清單給使用者選擇；select 產生 `selected.zip` 與 `bundle-manifest.json`，包含找到的選定聊天室附件。原始 ZIP 不修改。

清單綁定來源 ZIP 的檔案大小與修改時間；來源變更則重跑 list。工具不合併多個不同 ZIP 或猜身分，也不保證找到所有匯出版本；只有空清單／部分 JSON 不支援時報告限制、檢查實際結構，不能宣稱無訊息。

工具的解壓上限是資源保護值，可用 `--max-bytes` 明確調整，並非 ChatGPT 上傳限制。拒絕異常路徑、symlink、重名條目和大於上限的處理，且不覆蓋既有輸出。缺附件從 manifest 讀取，須讓使用者知道。

## 只有上傳入口的環境

不能在雲端 skill 裡憑空讀使用者電腦。優先交付上述瀏覽器工具；仍不可行時用簡明手動方式：

1. 在電腦解壓原匯出檔的副本。
2. 找到 messages/inbox 等訊息資料夾；名稱看不懂時，使用 message JSON 的 title／participants 確認。
3. 收集該聊天室所有 message JSON 與其引用的附件，保留原相對路徑後另行壓縮。附件可能在聊天室外，不要只留 message_1。
4. 若不會辨認，先上傳小份名稱清單或僅訊息 JSON 供辨認，之後補附件；明確標示初次資料不完整，不開始假完整分析。

單一對象仍太大：先把文字與附件分包，建立共用來源索引；每包是可獨立解壓的 ZIP，不使用需合併才能解壓的位元組分卷。可縮小圖片但保留原件與對應，聊天截圖縮圖後仍需可讀。不默默刪附件、不只留爭吵。若使用者明確選較短期間，顯示分析範圍。

LINE 直接提供私人聊天室 TXT，通常無需整包帳號備份。純文字過長仍需分段閱讀。上傳成功不代表完整閱讀，分包不消除模型的閱讀額度與時間成本。
